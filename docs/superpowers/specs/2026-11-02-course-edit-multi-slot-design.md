# 课程编辑：多时段与按日期添加 · 设计文档

- 日期：2026-11-02
- 状态：待实现
- 版本：1.3.0

## 1. 背景与问题

现在的课程模型是「星期几 + 一个节次区间 + 若干周次」，加一门课时：

1. 用户只知道「11 月 5 日周三有课」，但周次选择器只有 1、2、3…20，对不上日期，容易选错周。
2. 同一门课一周上多天（如周一、周三、周五）时，只能重复添加三次，而且各天的节次可能不同（周一 1–2 节、周三 3–4 节）。
3. 新加课程默认勾选 1–20 周，用户没注意就会得到一门"整学期"的课。

## 2. 目标

1. 一个页面里录入多个「星期 + 节次」时段。
2. 周次选择器能直接看到日期，并能按日期反查周次。
3. 支持"只上一次"的课（调课、补课），且不新增数据结构。
4. 不破坏已稳定的课表布局、今日页、冲突并排和导出导入。

## 3. 非目标

- 不支持学期范围外的单次课（不新增 `dates` 字段）。
- 不做课表格子点选（7 天 × 节次网格），先做一行行添加。
- 不改 JSON / CSV / ICS 导出格式。
- 不改课表页的触摸与分页逻辑。

## 4. 方案选择

### 多时段的两种存法

| 方案 | 做法 | 代价 |
|---|---|---|
| A. 多时段模型 | 课程内新增 `slots: [{day, startSection, endSection}]` | 需改布局、今日页、冲突、导出、解析、5 个测试文件，共 14 个文件 61 处引用 |
| **B. 多条记录 + 分组（采用）** | 每个时段存成一条独立课程，共享 `groupId` | 只需改课程编辑页和 store，其余逻辑零改动 |

选择 B 的理由：课表布局、今日页、冲突、导出都按"一条记录 = 一个时间点"实现，保持这个假设可以把回归风险降到最低。用户完全感知不到拆分成多条。

### 周次展示

采用「每个周次格子显示周号 + 该周周一日期」，并增加日期选择器作为精确入口。

## 5. 数据结构

课程记录保持不变，新增可选字段：

```js
{
  id: 'c_xxx',
  groupId: 'g_xxx',        // 新增：同一门课的多条记录共享；单独课程没有
  name: '高等数学',
  teacher: '张老师',
  location: 'A101',
  day: 1,                  // 1=周一 … 7=周日
  startSection: 1,
  endSection: 2,
  weeks: [1, 2, 3],
  colorIndex: 0,
  remark: '',
  credit: 3,
  source: 'manual',
  updatedAt: 0
}
```

兼容性：

- 旧数据没有 `groupId`，按独立课程处理，不需要迁移。
- 导出时 `groupId` 不写入 JSON/CSV/ICS，保持现有格式；导入后同组关系不保留，按独立课程处理。
- 周次仍然只存周号，不存日期。

## 6. 课程编辑页

### 6.1 上课时间（多时段）

```
上课时间
┌──────────────────────────────┐
│ 周一   第 1-2 节        删除 │
│ 周三   第 3-4 节        删除 │
└──────────────────────────────┘
+ 添加时间段
```

- 每行两个选择器：星期、起止节次。
- 至少保留一行；只剩一行时「删除」不可用。
- 保存前校验：不能出现重复的「星期 + 节次区间」。
- 只有一行时不生成 `groupId`。

编辑已有课程：

- 只有该课程带 `groupId` 且同组超过一条时，页面顶部才显示「☑ 同时修改这门课的其他 N 个时段」，默认勾选。
- 勾选时，名称、老师、地点、周次、颜色、备注、学分同步到同组其他记录；时段列表的增删也同步。
- 取消勾选时，只更新当前记录，并保留 `groupId`。
- 新增课程时没有分组，不显示该选项；保存后按时段数量决定是否生成 `groupId`。

## 7. 课程编辑页：周次与日期

```
上课周次                     已选 16 周
本周是第 10 周 · 11/03–11/09   [只选本周]
[全选] [单周] [双周] [清空]
按日期添加  2026-11-05  ▾

[已设为 11月5日（第 10 周）· 只这一次   改为每周都上]

 1     2     3     4     5
11/03 11/10 11/17 11/24 12/01
```

规则：

1. 新加课程默认 1–N 周全选（保持现有行为）。
2. 每个周次格子两行：周号 + 该周周一日期。
3. 顶部显示当前周，格式「本周是第 X 周 · 起始日期–结束日期」。
4. 未设置开学日期时：
   - 顶部换成「先设置开学日期才能按日期添加」，点击跳设置页
   - 日期选择器禁用，「只选本周」隐藏
5. 今天不在学期范围内时不显示「只选本周」。
6. 日期选择器范围：第 1 周周一 ~ 第 N 周周日。
7. 选完日期后：
   - 只勾选对应那一周
   - 只有一个时间段时，同时把该行星期改为日期所在星期
   - 有多个时间段时，只定位周次，不改任何行的星期，提示「已定位到第 X 周」
   - 显示提示条「已设为 M月D日（第 X 周）· 只这一次」
8. 点「改为每周都上」→ 全选，提示条消失。
9. 任何手动周次操作（点格子、全选、单周、双周、清空、只选本周）都清除提示条。

## 8. 删除

- 没有 `groupId`：沿用现有确认框。
- 有 `groupId` 且同组超过一条：用 `wx.showActionSheet` 提供两个选项：
  - 「删除整门课（N 个时段）」
  - 「只删除当前时段」

## 9. 边界与错误处理

| 情况 | 处理 |
|---|---|
| 未设置开学日期 | 日期选择器禁用，顶部提示跳转设置 |
| 今天在学期前/后 | 不显示「只选本周」 |
| 日期超出范围 | 选择器已限制；代码仍兜底 toast |
| 多时段时选日期 | 只改周次，不改星期 |
| 同组只剩一条 | 保留 `groupId` 无害，删除时不再弹选择 |
| 编辑教务导入课程 | 沿用现有逻辑：转为手动课程；同组记录一起更新 |
| 时段完全重复 | 保存前拦截并提示 |

## 11. 测试策略

单元测试：

- 日期 → (周次, 星期) 换算：周一、周日、跨月、学期第一周、最后一周、学期外。
- 周次日期标签：第 1 周、中间周、最后一周。
- 学期日期范围：正常、未设置开学日期。
- store：多时段保存生成同一 `groupId`；同组批量更新；删除整组；删除单条。

页面审计：新增 `bindtap` 均有处理函数，页面跳转已注册。

真机手工测试：

1. 添加一门课，三个时段，节次各不相同，保存后课表三处显示。
2. 编辑其中一个色块，改名并勾选「同时修改其他时段」，其余两个同步更新。
3. 删除时选「只删除当前时段」，另外两个保留。
4. 周次格子显示日期；点日期选择器选 11 月 5 日，只勾选对应周。
5. 点「改为每周都上」，变成全选。
6. 未设置开学日期时，日期选择器禁用并提示。

## 12. 风险

- 分组记录的日志式行为（改名同步）依赖编辑页的勾选项，用户取消勾选后可能产生不一致；这是可接受的产品取舍，通过提示文案说明。
- 导出不保留分组关系，重新导入后同组记录变成独立课程。可接受，因为导出主要用于备份与换机。
