# 候选学校连通性测试（2026-10-28）

## 测试方法

对每所学校执行三步：

1. `GET /jwglxt/xtgl/login_slogin.html`：检查是否有标准正方登录表单、`csrftoken`
2. `GET /jwglxt/xtgl/login_getPublicKey.html`：检查是否返回 `modulus` / `exponent`
3. 用**手机端同一套 RSA 代码**加密一个假密码，用不存在的学号提交登录

判断标准：

- 返回「用户名或密码不正确」→ 学校成功解开了密文，链路可用
- 返回「验证码输入错误」→ 需要验证码，自动导入不可用
- 403 / DNS 失败 / 连接超时 / 没有标准登录表单 → 当前不可用

> 这只验证了登录链路，**不等于真实导入一定成功**。还需要对应学校的真实账号；`verified` 只有真实导入成功后才会自动变成 `true`。

## 可用（5 所）

| 学校 | 学校管理里填的地址 | 说明 |
|---|---|---|
| 上海理工大学 | `https://jwgl.usst.edu.cn` | HTTPS，客户端 RSA 通过 |
| 西安邮电大学 | `https://zfjw.xupt.edu.cn` | 注意：**不要带 www**，`www.zfjw.xupt.edu.cn` 解析不到 |
| 许昌学院 | `https://jwglxt.xcu.edu.cn` | 已在内置白名单，客户端 RSA 通过 |
| 枣庄学院 | `https://jwgl.uzz.edu.cn` | 原地址是 HTTP，会 302 到 HTTPS，**直接填 HTTPS** |
| 江苏城市职业学院 | `http://jwc.js-cj.com` | 只有 HTTP 能通，HTTPS 超时；HTTP 安全性较低，建议先只自己测试 |

这 5 所的 `modulus` 都是 129 字节（1024 位带 Java 前导零），手机端密文都是 128 字节，说明 RSA 前导零修复对它们同样有效。

## 暂不可用（4 所）

| 学校 | 地址 | 原因 |
|---|---|---|
| 福建师范大学 | `https://jwglxt.fjnu.edu.cn` | 登录返回「验证码输入错误！」，需要验证码 |
| 浙江大学（本科） | `https://zdbk.zju.edu.cn/jwglxt` | 没有标准正方登录表单，走统一身份认证，当前不支持 |
| 济南大学 | `http(s)://jwgl.ujn.edu.cn` | 登录页返回 403，可能是 WAF/地区限制；不建议开放 |
| 上海应用技术大学 | `http(s)://jwxt.sit.edu.cn` | 80/443 均连接超时或被拒绝，公网访问不到 |

## 添加到学校管理

1. 「我的」→ 长按「隐私说明与开源声明」→ 学校管理
2. 新增学校，填上表中对应的地址
3. 打开「开放自动导入」
4. 「已实测通过」先不要打开，等真实账号导入成功后云函数会自动标记
5. 保存后约 1 分钟生效，用户重新打开学校列表或下拉刷新

江苏城市职业学院是 HTTP，如果介意安全性，可以保持「开放自动导入」关闭，只作为手动添加的学校条目。

## 结论

- 上海理工大学、西安邮电大学、许昌学院、枣庄学院：可以添加并开放自动导入
- 江苏城市职业学院：可以添加，但 HTTP 有安全风险，建议先小范围测试
- 福建师范大学、浙江大学、济南大学、上海应用技术大学：暂不支持，保持仅手动
