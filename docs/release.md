# 版本更新与发布

## 结论

- 更新期间用户**不会用不了**，没有停机窗口
- 提交审核的是开发版本，线上旧版本一直正常服务
- 发布后旧版本用户不会立刻被强制更新，通常下次冷启动才用新代码
- 项目采用**无感知更新**：不弹更新提示，新版本下载完成后，用户下次冷启动自动使用新版

## 一次完整发版流程

1. 本地开发、跑测试

   ```bash
   npm test
   npm run audit
   ```

2. 真机/体验版验证
3. 开发者工具「上传」，版本号递增，例如 `1.1.0`
4. 公众平台 → 管理 → 版本管理 → 设为体验版，扫码验证
5. 验证通过 → 提交审核
   - 审核期间线上版本不受影响
   - 审核一般 1–7 天，可能来电
6. 审核通过 → 发布
   - 如果支持分阶段发布，建议先 10%，观察日志和反馈，再逐步放量
7. 用公告功能通知用户更新内容

## 用户什么时候真正用上新版本

微信客户端会缓存小程序代码，不是发布后立刻替换：

1. 发布新版本后，用户第一次冷启动：先用旧版运行，微信在后台检查并下载新包
2. 下载完成：新包保存在本地，本次仍然用旧版
3. 用户下一次冷启动：自动使用新版，不需要点击任何按钮

这就是「无感知更新」：用户不会看到更新弹窗，也不会被打断。

注意：

- 如果用户长期不彻底关闭小程序，可能一直用旧版
- 下载中途退出、断网，旧版不受影响，下次冷启动继续检查
- 只要云函数和数据结构向后兼容，旧版用户不会出问题

如果以后想改成有感知，可以在 `app.js` 里接入 `wx.getUpdateManager()`，在 `onUpdateReady` 时弹窗提示重启。

## 云函数和数据库可以单独更新

云函数部署、数据库改字段**不需要审核**，发布后立即生效。因此建议：

1. 先做向后兼容的云函数/数据库变更
2. 再发布小程序客户端
3. 等旧版本用户基本升级后，再清理旧逻辑

### 兼容原则

- 只**新增**字段，给旧数据默认值
- 不要删除、改名旧客户端仍在读的字段
- 不要改变已有云函数的返回结构
- 必须改协议时，新建一个云函数或加版本参数，让新旧客户端并存

### 1.2.1 教务导入修复：先云函数，后客户端

示例学校导入失败是两个问题叠加（详见 `docs/client-encryption.md`）：

1. 学校按会话轮换 RSA 公钥，手机端另开会话取到的公钥和云函数登录会话不匹配
2. 1024 位公钥的 `modulus` 带 Java 前导零，手机端把密钥长度算成 129 字节，PKCS#1 填充多一字节，解出来的明文错误

1.2.1 的修复：

- 云函数新增 `action: 'prepare'`，建会话取公钥，手机加密后用同一会话登录
- `miniprogram/utils/rsa.js` 去掉 `modulus` 前导零后再计算密钥长度，密文从 129 字节恢复为正确的 128 字节

发版顺序：

1. 先部署 `syncSchedule` 云函数（同时兼容 1.2.0 旧请求）
2. 再上传 1.2.1 小程序并提交审核
3. 旧版 1.2.0 对示例学校仍会失败，用户升级后恢复；公钥固定的学校不受影响

不要先发客户端：新客户端会调用旧云函数没有的 `prepare`，导入会直接失败。RSA 修复在客户端，云函数部署后仍需重新上传小程序才会生效。

### 1.3.0 学校管理：之后加学校不用发版

1.3.0 把「哪些学校开放自动导入」从客户端代码搬到云数据库 `schools.autoImport`，并新增管理员学校管理页。

部署顺序：

1. 部署 `manageSchool` 云函数
2. 给 `manageSchool` 配置 `ADMIN_OPENIDS`（和管理公告的函数同一个值）
3. 重新部署 `listSchools`（返回 `autoImport`）
4. 重新部署 `syncSchedule`（按 `autoImport` 放行，缓存改为 60 秒）
5. 上传 1.3.0 小程序

之后新增学校：

- 「我的」→ 长按「隐私说明与开源声明」→ 学校管理 → 新增
- 不需要改代码、上传或审核
- 约 1 分钟生效

详细操作见 `docs/school-admin.md`。

## 本地存储兼容

课表、设置、已读状态都存在用户手机本地，升级不会清空。

改数据结构时：

- 保留旧的 storage key，或在 `store.ensureDefaults()` 里做迁移
- 新字段必须有默认值，不能假设旧数据存在
- 不要直接改 key 名，否则用户数据看似丢失

## 回滚

- 小程序：版本管理里可以回退到上一个线上版本
- 云函数：重新部署上一个版本
- 数据库：只做加法，回滚时通常不需要动数据

## 紧急修复

- 云端问题：改云函数立即部署，不用等审核
- 客户端问题：仍需上传 + 审核；如有加急审核额度可以使用
- 严重问题可先回滚线上版本，再慢慢修
