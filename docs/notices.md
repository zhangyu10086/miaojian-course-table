# 公告功能使用说明

首页右上角的铃铛图标用于查看公告。有未读公告时显示红点；点开后进入公告列表，再点「查看详情」阅读全文。

## 功能规则

- 只能置顶 **1 条**公告，置顶后永远排在最前
- 其余公告按发布时间从新到旧排列
- 未读公告标题前是**蓝色呼吸圆点**，已读变成**灰色圆点**
- 打开公告详情才算已读；所有公告都读过后，首页铃铛红点消失
- 浏览量按微信 openid 去重，同一用户反复打开只算一次
- 发布来源固定显示「金枪鱼2026」
- 公告详情显示发布时间、更新时间、浏览量和全文

## 一次性配置

### 1. 创建两个集合

云开发控制台 → 数据库，新建：

| 集合 | 用途 | 权限 |
|---|---|---|
| `notices` | 公告内容 | 所有用户不可读写 |
| `notice_views` | 浏览记录（按用户去重） | 所有用户不可读写 |

小程序端不直接读数据库，统一通过云函数访问，所以权限都锁死。

### 2. 部署四个云函数

右键以下目录，分别选择 **上传并部署：云端安装依赖**：

- `cloudfunctions/listNotices` — 公告列表
- `cloudfunctions/viewNotice` — 公告详情 + 浏览量
- `cloudfunctions/publishNotice` — 发布公告
- `cloudfunctions/manageNotice` — 管理公告（列表、编辑、删除、置顶）

### 3. 配置管理员 openid

`publishNotice` 和 `manageNotice` **两个云函数都要配**：

云开发控制台 → 云函数 → 选中函数 → 配置 → 环境变量：

```
变量名：ADMIN_OPENIDS
变量值：你的 openid
```

多个管理员用英文逗号分隔。

> 只配 `publishNotice` 的话，可以发布，但公告列表和编辑/删除/置顶会提示没有权限。

### 4. 进入管理页

打开小程序「我的」页，**长按「隐私说明与开源声明」**，进入管理员页，再点「公告管理」。

1.3.0 起管理员页同时包含「公告管理」和「学校管理」，并会显示两个云函数的权限状态。

管理员身份状态统一在管理员页底部「刷新管理员状态」里刷新，公告管理页不再单独放刷新按钮。

首次进入如果还没配好 openid，页面会显示当前微信的 openid 和配置步骤。

## 日常使用

### 发布公告

管理页顶部填写标题和正文，点「发布公告」。发布时间和更新时间由服务器自动写入。

如果需要让用户一键复制交流群号，在「交流群号（选填）」里填 5–15 位数字，例如 `1124141900`。只有填了群号的公告，详情页才会显示「复制群号」按钮；其他公告不受影响。

### 正文支持的基础 Markdown

| 语法 | 效果 |
|---|---|
| `# 标题` | 大标题 |
| `## 小标题` | 小标题 |
| `### 更小标题` | 更小标题 |
| `**加粗**` | 加粗 |
| `- 列表` | 无序列表 |
| `  - 子列表` | 缩进两格显示为子列表 |
| `1. 列表` | 有序列表 |
| `> 引用` | 引用块 |
| 空行 | 分段 |

不支持图片、外链、表格、代码块和原始 HTML。列表摘要会自动去掉这些标记，只显示纯文字。

### 置顶

在「公告列表」里点某条公告的「置顶」。再置顶另一条时，原来的会自动取消，始终只有一条置顶。

### 编辑

点「编辑」进入编辑页，只能修改标题和正文；保存后 `updatedAt` 自动更新，详情页会显示「更新于 X」。

### 删除

点「删除」，确认后彻底删除，不可恢复。

## 数据字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `title` | 字符串 | 公告标题 |
| `content` | 字符串 | 公告正文，纯文本，支持换行 |
| `source` | 字符串 | 固定「金枪鱼2026」 |
| `qqGroup` | 字符串 | 可选，交流群号，5–15 位数字；填写后详情页显示「复制群号」 |
| `views` | 数字 | 去重后的浏览量 |
| `pinned` | 布尔 | 是否置顶，最多一条为 true |
| `publishedAt` | 数字 | 发布时间戳（毫秒） |
| `updatedAt` | 数字 | 最后编辑时间戳；发布时等于发布时间 |
| `visible` | 布尔 | 填 `false` 可以隐藏 |

旧公告如果没有 `source`、`views`、`updatedAt`，会自动按「金枪鱼2026」、0 次浏览、发布时间处理。

## 浏览量

`viewNotice` 在用户打开详情时执行：

1. 用 `公告id_openid` 作为 `notice_views` 的记录主键
2. 没有记录才把 `notices.views` 加 1
3. 同一用户重复打开不会重复计数

如果 `notice_views` 集合不存在，详情还能打开，但浏览量不会增加。

## 请求频率

公告列表不会轮询、不会每秒请求：

- **冷启动、从后台回到前台**：强制检查一次公告，保证打开就能看到红点
- 页面内切 tab 或从其他页面返回：本地缓存不超过 **2 分钟**就直接读缓存
- 用户在课表页停留时，每 60 秒检查一次，超过 2 分钟才真正请求
- 用户主动点开公告时，最多 **10 秒**请求一次
- 公告列表打开期间暂停 60 秒定时检查，用户阅读时不会自动刷新或跳动
- 关闭公告列表后恢复定时检查
- 页面隐藏或离开时停止检查，不做无意义请求
- 只有打开公告详情才调用 `viewNotice`

这样用户每次打开小程序都会检查一次，停留期间最迟约 2–3 分钟刷新，请求量仍然可控。

## 未读状态

- 已读的公告 id 保存在用户手机本地（`ct_notices_read_v1`）
- 打开详情页才标记已读
- 清除小程序缓存会重置已读状态，所有公告重新变成未读
- 首页铃铛红点只是「是否还有未读」的汇总提示，和列表里的蓝点是同一套状态

## 注意事项

- 公告正文是纯文本，不支持 HTML
- 单条正文建议控制在 500 字以内
- 公告会展示给所有用户，不要写手机号、身份证等个人信息
- 撤回公告优先删除；暂时隐藏可以把 `visible` 改成 `false`
