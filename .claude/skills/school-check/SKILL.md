# 学校适配检测

## 什么时候用

用户想给「秒见课表」新增一所学校，但不确定：

- 这所学校是不是新版正方 `jwglxt`
- 教务系统能不能从公网访问
- 有没有验证码、SSO、WAF
- 学校管理里的三个框该填什么
- 搜索别名该写哪些

## 输入

需要两样东西：

1. **学校名称**，例如 `上海理工大学`
2. **任意相关地址**，可以是：
   - 学校官网：`https://www.usst.edu.cn`
   - 教务处页面
   - 教务系统首页
   - 教务系统登录页
   - 课表查询页

如果用户只给了学校名，先用 WebSearch 搜索：

```
学校名 教务处 教务系统 正方
```

优先选 `.edu.cn` 官方地址，找到后再运行脚本。不要凭空猜域名。

## 运行脚本

在项目根目录执行：

```bash
node scripts/check-school.js --name "学校名称" --url "用户给的地址"
```

脚本会：

- 从官网/教务处页面里找教务系统入口
- 尝试 `jwgl`、`jwxt`、`jwc`、`jwglxt`、`zfjw`、`zhjw`、`oaa` 等常见子域
- 自动处理 http → https 跳转
- 检查登录页表单、`csrftoken`、公钥接口
- 用**手机端同一套 RSA** 加密一个假密码，用不存在的学号提交一次
- 把结果写到 `docs/school-check-result.json`

运行后**必须用 Read 工具读取 `docs/school-check-result.json`**，不要只依赖终端输出（中文可能乱码）。

## 判断结果

读取 JSON 里的 `verdict`：

| verdict | 含义 | 能不能开放自动导入 |
|---|---|---|
| `usable` | 登录接口正常，学校成功解开了手机端密文 | 可以尝试 |
| `captcha` | 需要验证码/滑块 | 不可以 |
| `sso` | 统一身份认证/SSO，没有标准正方表单 | 不可以 |
| `no_form` | 没有标准正方登录表单 | 不可以 |
| `no_key` | 公钥接口不可用 | 不可以 |
| `no_csrf` | 登录页缺少 csrftoken | 不可以 |
| `forbidden` | 403，可能被 WAF/地区限制 | 暂时不可以 |
| `unreachable` | DNS/超时/连接被拒绝，可能只允许校园网 | 不可以 |
| `unknown` / `login_redirect` | 返回非标准页面 | 需要人工确认 |

## 输出格式

### 可以尝试

```
结论：可以尝试自动导入。

学校管理三栏：
学校名称：上海理工大学
教务地址：https://jwgl.usst.edu.cn
搜索别名：shanghailigongdaxue, shlgdx, 上海理工, shanghailigong, usst

依据：
- 登录页正常，有 csrftoken
- 公钥接口正常，密钥 129 字节（1024 位）
- 手机端密文 128 字节
- 用不存在的学号提交，学校返回「用户名或密码不正确」，说明密文已被成功解开

注意：
- 这只是链路验证，真实导入还需要该校真实账号
- 「已实测通过」先不要手动打开；真实导入成功后云函数会自动标记 verified
- 保存后约 1 分钟生效，用户重新打开学校列表或下拉刷新
```

### 不可以

```
结论：暂时不能自动导入。

原因：登录需要验证码/滑块。

建议：
- 用户仍然可以手动添加课程
- 可以用 JSON / CSV / ICS 导入课表
- 不要在学校管理里打开「开放自动导入」
```

## 规则

- **不要向用户索要真实账号密码**。脚本只用不存在的学号做一次登录尝试。
- 每所学校只做一次登录尝试，不要反复提交，避免触发锁定或 WAF。
- `usable` 只代表「可以尝试」，不代表真实导入一定成功。
- 不要修改学校数据库、不要调用 `manageSchool`，只输出用户要填的三栏。
- 如果脚本没找到教务入口，用 WebSearch 找学校教务处地址后再运行一次。
- 旧版正方（`default2.aspx`）、强智、URP、Kingsosoft、统一身份认证都不在当前支持范围，直接说明不支持。
- 如果用户给的地址是 HTTP，脚本会尝试 HTTPS；如果最终只有 HTTP 可用，要提醒用户 HTTP 的安全性较低。
- 别名输出 3–6 个，用英文逗号加空格分隔。脚本已经会生成全拼、首字母、中文简称和域名缩写。
